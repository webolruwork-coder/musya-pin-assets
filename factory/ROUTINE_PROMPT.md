# Pinterest Daily Factory

Основная конфигурация разделена на две Scheduled tasks:

- `ROUTINE_PRODUCER.md` — 15 запусков в день, по одному пину на завтра;
- `ROUTINE_PUBLISHER.md` — один ночной запуск, который публикует только одобренные пины.

Эта инструкция описывает общий контракт одного пина и сохраняется как справочник.

Рабочая папка: канонический репозиторий `musya-pin-assets` с этой инструкцией.

## Цель

Поддерживать очередь оригинальных Pinterest-пинов для `musya_gpt` с целевой ссылкой `https://musya.app/image-generation`. Один производственный запуск обрабатывает максимум один manifest. Дневной лимит — 15 публикаций.

## Алгоритм запуска

1. Выполни `npm run factory:init` и `npm run factory:next`.
2. Если активного запуска нет, создай его командой:

   ```bash
   npm run factory:create -- --slug <короткий-английский-slug>
   ```

3. На стадии `queued` сначала открой глобальную публичную выдачу Pinterest по точному запросу `промпт` и собери первые 25 organic результатов. Из ответа `BaseSearchResource` сохрани pin ID, позицию и оригинальное изображение. Командой `factory:research-pinterest` получи доступные публичные сохранения из метаданных карточек. Затем запроси через Metricool MCP аналитику собственных Pinterest-пинов за 30 дней только для дополнительной проверки:
   - визуально открой минимум три изображения; список URL без просмотра картинки исследованием не считается;
   - просмотри не более `search.result_limit` внешних карточек;
   - исключи рекламу;
   - остановись через `timeout_seconds`, даже если результатов меньше;
   - ранжируй по публичным сохранениям, затем по позиции в выдаче и повторяемости паттерна; отсутствующие метрики оставляй `null`;
   - выбери один основной референс с ненулевыми публичными сохранениями и запиши его URL, `public_saves` и `search_rank` в `research_evidence`;
   - отдельно перечисли 3–5 признаков, которые переносим, и признаки, которые намеренно меняем;
   - запиши URL и SHA-256 fingerprint, затем кратко опиши общие паттерны;
   - не скачивай и не копируй чужой пин как основу финального изображения;
   - переведи manifest в `research_ready`.
4. Подготовь вариацию выбранного сильного паттерна. Не придумывай сюжет с нуля и не смешивай больше двух паттернов. Используй тот же тип композиции, материала, света и плотности кадра; измени объект, геометрию и текст настолько, чтобы получилась самостоятельная работа. Заполни title, description и 7–10 ключевых фраз. Переведи в `concept_ready`.
5. Создай оригинальное вертикальное изображение 2:3 через ImageGen. Сохрани исходник внутри папки запуска и переведи в `generated`.
6. Используй локальный SVG-рендерер: изображение остаётся главным, текст живёт в спокойной области, CTA ведёт на `https://musya.app/image-generation`. Финал — JPEG или PNG ровно `1000×1500`. Переведи в `rendered`.
7. Выполни `npm run factory:validate -- <run-id>`.
   - При ошибке оставь `needs_review`, запиши причину и прекрати запуск.
   - После успешной автоматической проверки визуально проверь мобильную читаемость, отсутствие логотипов, водяных знаков и анатомических дефектов.
8. Выполни `npm run factory:review`. У production manifest успешная валидация автоматически записывает `approval.status = approved`; при любой ошибке остановись в `needs_review`.
9. Издатель выполняет `npm run factory:prepare-host -- <run-id>`, отправляет публичный файл и запускает `factory:confirm-host`; команда переводит manifest в `hosted` только после успешной HTTP-проверки изображения.
10. Если публикация выключена, остановись и сообщи ссылку на manifest и превью.
11. Если публикация включена, проверь Metricool на дубль по `id`, выбери бренд по `blog_id` и через Metricool MCP поставь пин в очередь на доску из manifest. Числовой `boardId` не требуется: используй точное имя доски. Запиши post ID и время, переведи в `scheduled`.

## Запреты

- Не листай бесконечную выдачу Pinterest.
- Не используй Pinterest API.
- Не публикуй напрямую в Pinterest: только Metricool.
- Не перескакивай через стадии и не используй `--force`.
- Не повторяй reference URL из других manifest.
- Не переходи в `concept_ready`, если основной референс не открыт визуально, найден вне глобальной выдачи `промпт` или у него нет позиции и публичных сохранений.
- После изменения глобального шаблона сначала запусти автоматические тесты и полный quality gate на одном экземпляре.
- Не меняй глобальный шаблон по результатам одного пина.
- Производитель не пушит в `main` и не публикует. Издатель действует только по `ROUTINE_PUBLISHER.md`.
